# 日历邀请

`.ics`（iCalendar）可以在 `LOCATION`、`DESCRIPTION`、`URL`、`ATTACH` 里放外部引用。部分客户端在渲染、提醒或用户点击时会去访问，从而在 Windows 上触发 SMB/HTTP 认证。

**收到邀请 ≠ 会认证。** 版本和「阻止自动下载外部内容」会让同一份邀请完全没流量。必须先有日志，再谈哈希或中继。

## 字段在做什么

| 字段 | 可能发生的事 |
|---|---|
| `LOCATION` | 放 UNC 时，有的客户端或用户点击「位置」会走 SMB |
| `DESCRIPTION` | URL 或 UNC；HTML 正文可能拉外部图 |
| `URL` | 阅读窗格 / 点击 |
| `ATTACH` | 「预览附件」时抓取 |

Outlook 默认常阻止自动下载。不要押注单一字段。实验室里可以在**同一份邀请**里放一个 SMB 引用和一个 HTTPS 探针，让日志告诉你客户端碰了哪个。HTTPS 探针只用来证明「客户端会抓外部内容」，不要把机密放 URL。

本站不提供可投递的 `.ics` 武器文件。RFC 5545 的字段是公开的，自己在实验网写最小邀请即可。

## 认证之后

若日志里出现 Net-NTLMv2：

- 中继：仅当目标 SMB 签名未强制，且在授权范围内，见 [MSSQL](/topics/mssql) 里同样的签名检查
- 破解：看授权范围是否允许离线破解；现代域密码策略下价值有限

客户端若不是 Windows，通常没有 NTLM 哈希，只有 HTTP 请求。

## 失败分类

| 现象 | 先查 |
|---|---|
| 邀请已发送，攻击机零流量 | 客户端没解析外部内容；出网策略；字段被剥掉 |
| 只有 HTTPS 探针，没有 SMB | 客户端不碰 UNC；或用户没点位置 |
| 有 SMB 但没有可中继目标 | 签名强制；只能评估是否允许破解 |

## 防御侧

- 客户端阻止自动下载外部内容
- 出站 SMB 默认拒绝
- 邮件网关检查日历附件里的 UNC
- 全网 SMB 签名
