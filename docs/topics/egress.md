# 出网通道

代码能执行，会话出不来，是另一类问题。先验证**路径**，再让每个阶段走同一条路径。

## 先画路径卡片

每一阶段记下：

| 字段 | 例 |
|---|---|
| 地址 | `LHOST` 还是跳板地址 |
| 端口 | 443 / 80 / 53 |
| 协议 | HTTP / HTTPS / TCP / DNS |
| 代理 | 直连 / 用户 IE 代理 / WinHTTP |

第一阶段用 HTTP 80、第二阶段用 HTTPS 443 且证书不被信任，看起来像「分阶段失败」，其实是两张卡片。

## 用户 vs SYSTEM

用户会话能回连、提权到 SYSTEM 后失联，优先查代理：

| 上下文 | 常见代理来源 |
|---|---|
| 用户 | WinINet / IE / `netsh winhttp import proxy source=ie` 之前的用户设置 |
| SYSTEM / 服务 | WinHTTP 机器级代理；常常是「空」 |

```cmd
netsh winhttp show proxy
netsh winhttp import proxy source=ie
```

`netsh winhttp set proxy` 影响整机。实验里先保存原值，用完 reset。授权测试中改机器代理要写进报告，并评估对其它服务的影响。

浏览器能上网、自定义程序不能：程序可能没走系统代理。实验载荷需要显式使用默认代理或 WinHTTP，而不是假设直连。

## 分阶段

Stager 从 `URL` 拉第二阶段。验证顺序：

1. 无害回调证明能出网
2. 投递日志是否出现第二阶段的 GET
3. 监听是否出现会话

有 GET 无会话：第二阶段内容、位数或回连地址有问题。无 GET：出网或 URL 写错，不是「免杀」问题。

目标完全不能访问你的文件服务器时，只能改用**内嵌**（单文件里带齐逻辑）。内嵌更大、静态特征更多，见 [AppLocker 与 AMSI](/topics/applocker-amsi)。两套都在实验网准备，现场不要现编。

## HTTPS

自签证书、TLS 版本、SNI、User-Agent 都可能导致「能 TCP 不能 TLS」。排错先对证书指纹、再看握手失败发生在哪一侧。代理会看到 Host / SNI，不要把机密放在 URL 查询串里。

## DNS 与域前置（概念）

HTTP(S) 和常规代理都不通、但实验规则允许 DNS 时，公开工具是 dnscat2、iodine 一类。它们流量特征明显，只在规则允许时用。本站不提供自定义 DNS C2 协议实现。

域前置依赖「客户端连的是被放行的前端，HTTP Host 指向后端」。现代 CDN 大量关闭这条路径。没有事先用无害 GET 验证过路由，不要把实验建立在它上面。

## 防御侧

- 出站默认拒绝；SYSTEM 不要能随便出网
- 强制代理 + TLS 检查
- 监控高频异常子域、长标签 DNS
- 用户代理与服务账户代理分离，避免提权后自动继承出网
