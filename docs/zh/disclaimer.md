## 1. 课程定位：高级渗透测试 vs 红队评估（PEN-300 §2.1）

根据 `pen-300.pdf` 第 2.1 节（*About The PEN-300 Course*），在进入具体技术模块前必须明确以下边界：

| 维度 | 高级渗透测试（PEN-300 核心范畴） | 红队演练 / 对手模拟（非本课程范畴） |
|---|---|---|
| **核心目标** | 检验客户组织 **IT 基础设施**（含加固终端、生产系统与 Active Directory）的安全性，尽可能深入并接管内网资产 | 检验并训练客户组织安全团队（**蓝队 / Blue Team**）的监测、告警与应急响应能力 |
| **对抗重心** | **绕过自动化安全机制**（客户端执行控制、杀毒软件 AV、应用白名单 AppLocker/CLM、AMSI、网络过滤与代理检查） | 模仿特定高级威胁组织（APT）的 TTP，重点在于全程规避人工蓝队的持续监控与溯源 |
| **常见入口形态** | **外部渗透测试（External Pentest）**：利用社工钓鱼（Office 宏、HTA、JScript、ICS 日历、ZIP 旁加载）或外网 Web 服务突破边界；<br>**假定失陷测试（Assumed Breach）**：客户提供低权限内部账号或立足点，重点评估内网横向与域控接管 | 往往结合物理、供应链或多周期隐蔽驻留，强调低噪与长期潜伏 |

> **核心结论**：PEN-300（*Evasion Techniques and Breaching Defenses*）是在 PEN-200（OSCP）基础上进阶的**高级渗透测试课程，而不是红队课程（It is not a Red Team course）**。实验与考试的核心是打通“自动化防御机制拦截下的完整攻击链”，无需为了追求花哨的现代 EDR/蓝队对抗而把利用链复杂化。

## 2. 适用范围与学术诚信边界（PEN-300 §1 & §2.2.3）

### 允许的场景

- **OffSec 官方托管实验网与考试环境**：在有效订阅或课程有效期内，通过官方 VPN 连接包访问的隔离靶场。
- **个人本地隔离实验室**：在与外网及生产环境隔离的本地虚拟机（VMware / VirtualBox 等）中复现与调试。
- **持有书面授权的渗透测试**：在客户签署的书面授权范围（Scope）、时间窗与交战规则（RoE）内开展的合规测试。

### 严格禁止的行为

- **未授权目标测试**：禁止对任何非本人所有或未获书面授权的互联网主机、企业内网或第三方平台执行扫描、投递或利用。
- **违反 OffSec 知识产权与学术政策（Academic Policy）**：
  - 严禁在第三方平台、公开代码仓库或社交媒体上传播、复制或泄露 `pen-300.pdf` 原文、配套视频或商业化衍生内容；
  - 严禁在论坛、公开博客或仓库中发布完整的 Challenge / 考试机器解题剧透（Spoilers）与 flag；
  - 根据 `pen-300.pdf` 第 1 章声明，违反 OffSec 学术政策（[https://www.offsec.com/legal-docs/](https://www.offsec.com/legal-docs/)）将导致**撤销已获得的全部 OffSec 认证、终身禁考及终身禁止购买 OffSec 课程**。

## 3. 实验网环境机制与行为准则（PEN-300 §2.4）

### 3.1 靶机分配与模块切换机制（§2.4.1–§2.4.4）

- **独立独占环境**：PEN-300 实验网中的所有虚拟机均为**按学员独立分配（Dedicated）**，不与其他学员共享。环境分为两类：
  1. **章节练习靶机（Module VMs）**：配合各章教材与练习使用（操作系统涵盖 Windows 10、Windows Server 2019、Ubuntu 20.04 等）；
  2. **综合挑战靶场（Challenges）**：完成课程模块后用于模拟黑盒渗透测试的完整内网环境（**不提供任何初始凭据**）。
- **单模块互斥运行**：不能同时激活多个章节的客户端靶机。在控制面板（Control Panel）切换到新模块时，当前模块的靶机将被自动移除。
- **攻击机基线（§2.4.4）**：课程命令默认基于 **64 位最新稳定版 Kali Linux（运行于 VMware，以非 root 普通用户执行命令）** 编写；复制 PDF 中的代码片段时，注意排查因排版折行引入的多余空格或换行符（§2.3.2）。

### 3.2 靶机重置（Reverts）规则（§2.4.2）

- **每日配额与冷却时间**：每名学员每 24 小时拥有 **12 次**重置额度，每日 **00:00 GMT+0** 自动重置计数器；两次重置之间至少间隔 **5 分钟**（额度用尽可联系 Live Support / Student Administrator 重置）。
- **整组重置（不支持单机重置）**：为保证 Active Directory 域环境的稳定性，**无法单独重置某一台虚拟机**。触发 Revert 时，当前模块或 Challenge 下的**全部虚拟机将同时恢复初始状态**（后半程多机模块耗时较长）。
- **VPN 断连自动回收**：若与实验网 VPN 断开连接较长时间，当前激活的靶机将被自动回收；重新连接 VPN 后必须先请求一次 Revert。**断开 VPN 前务必将靶机上编写的脚本、采集的凭据和笔记拷回 Kali 本机。**

### 3.3 实验网三大铁律（PEN-300 §2.4.5 Lab Restrictions）

::: danger 实验网强制禁令（违反将被停用实验网权限）
在 PEN-300 内部 VPN 实验网中，OffSec 严格执行以下三条禁令：
1. **禁止 ARP 欺骗、投毒或任何中间人攻击（MITM）**：不得对实验网执行 ARP Spoofing 或全网广播投毒（注：在日历邀请 M16 或 SQL 触发认证 M11 场景中，仅针对明确向你攻击机 IP 发起的定向连接做监听/中继，严禁在网段内开启主动欺骗投毒）。
2. **禁止对 VPN 基础设施进行暴力破解（Brute Force）**。
3. **禁止尝试攻击其他学员的客户端机器或 Kali 攻击机**。
:::

## 4. OSEP 考试规则与工具边界（PEN-300 §2.5 & Exam Guide）

### 4.1 考试时间窗与通过标准（§2.5）

| 项目 | 官方规定（以开考当天最新 [OSEP Exam Guide](https://help.offsec.com/hc/en-us/articles/360050293792-OSEP-Exam-Guide) 为准） |
|---|---|
| **考前核验** | 必须提前 **15 分钟**进入监考端完成身份核验与考前检查，随后获取考试专用 VPN 连接包 |
| **实操时长** | **47 小时 45 分钟**（完全独立分配的封闭企业网靶场，全程远程监考） |
| **报告时长** | 实操结束后额外 **24 小时**用于整理并上传渗透测试报告 |
| **通过条件** | 攻破指定的最终核心目标网段，**或**通过攻破单台主机累计获得至少 **100 分**（PEN-300 §2.5） |
| **评分周期** | 报告提交确认后 **10 个工作日内**返回成绩 |

### 4.2 工具使用边界（OSEP Exam Guide，`pen-300.pdf` 未涉及）

`pen-300.pdf` 不规定考试可用工具。以下边界来自 OSEP Exam Guide；以当期官方指南为准，考前务必重新核对。

- **允许使用**：标准开源攻防工具（Kali 自带包、Impacket、Mimikatz、Rubeus、Certipy、Chisel、Ligolo-ng、NetExec、evil-winrm、Metasploit Framework Community），以及自行编写或修改的 C / C# / PowerShell / JScript / VBA 代码。
- **严禁使用**：商业版或自动化漏洞利用平台（`Cobalt Strike`、`Metasploit Pro` 等）、任何形式的网络欺骗投毒（`ARP`/`DNS`/`NBNS`/`IP` Spoofing），以及对话式 AI 辅助工具。

### 4.3 证据截图与报告可复现性要求

- **Proof 文件**：每台主机的 proof 文件名（低权限立足点 `local.txt`，高权限 `proof.txt`）与最终目标由官方 Exam Guide 规定；`pen-300.pdf` 未定义这些文件名，考前以当期指南为准。
- **同屏原始证据**：每张 flag 截图必须在**同一终端窗口**中同时完整展示目标机 IP 地址（Windows 执行 `ipconfig`，Linux 执行 `ifconfig` 或 `ip addr`）与原始文件内容（`type` 或 `cat` 完整路径），不得裁剪终端上下文，也不得用远程读取或图形界面复制代替。
- **过程完全可复现**：报告评分不仅看是否拿到 flag，更看重攻击链的完整性与可复现性。所有修改过的源码、分段 payload 与关键执行命令均需完整贴入报告。

## 5. 本站排错纪律与统一占位符约定

### 排错纪律（Troubleshooting Discipline）

1. **先确认投递，再怀疑免杀**：载荷无回连时，先检查攻击机 HTTP / SMB 投递日志是否收到请求，区分“根本没触发/没下载”与“落地后被静态或行为查杀”。
2. **先探测位数与防御，再投递实弹**：生成任何 Windows 载荷前，先确认宿主进程位数（x86 vs x64）、PowerShell 语言模式（`FullLanguage` vs `ConstrainedLanguage`）、AppLocker 有效规则及出网通道（直连 / 系统代理 / DNS）。
3. **一次只改一个变量**：分阶段链路（Stager → Stage 2）必须走**同一条已验证可达的通信路径**；每次排错只调整单一变量并记录结果，同一向量受阻超过 30 分钟立即切换备选分支（详见 [00-environment-and-infra](/zh/modules/00-environment-and-infra) 与 [97-exam-day-lookup](/zh/modules/97-exam-day-lookup)）。

### 统一占位符（全站 20 个模块通用）

所有文档与脚本统一使用以下 9 个占位符，复制命令或编译脚本前请按实际环境替换：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `LHOST` | 目标可达的攻击机（或跳板监听端）IP 地址 | `192.168.45.172` |
| `LPORT` | 攻击机或跳板监听端口 | `443` / `4444` |
| `TARGET` | 目标主机 IP 地址或 FQDN 主机名（Kerberos 必须用 FQDN） | `192.168.152.150` / `dc01.corp.local` |
| `DOMAIN` | Active Directory 域名 | `corp.local` |
| `USER` | 认证用户名（本地或域账户） | `offsec` / `sqlsvc` |
| `PASS` | 明文密码 | `Password123!` |
| `NTHASH` | NTLM 哈希值（32 位十六进制，用于 PTH / 票据申请） | `8846f7eaee8fb117ad06bdd830b7586c` |
| `PAYLOAD` | 投递或落地的载荷文件名 | `runner.exe` / `stage2.ps1` |
| `URL` | 我方 HTTP(S) 投递服务完整地址 | `http://192.168.45.172/stage2.ps1` |
