# 失败排查

实验里最常见的浪费是：失败后立刻换编码、换工具、换入口，却没分清失败发生在哪一层。

```
没有预期结果
├─ 投递日志没有请求
│     → 用户没打开 / 网关丢掉 / URL 写错 / 换投递通道（HTTP / SMB / 邮件）
├─ 有请求，但没有执行痕迹
│     → 静态特征、扩展名策略、宏被禁用、脚本宿主被拦
├─ 执行了但立刻退出
│     → 位数不匹配、缺依赖、DLL 导出不全、宿主闪退
├─ 执行了但进程被杀掉
│     → 行为检测；换实现形态之前先定位是「分配内存 / 建线程 / 出网」哪一步
├─ 第一阶段通、第二阶段没有
│     → 地址、端口、协议或代理上下文不一致
└─ 会话建立后很快断
      → 宿主生命周期（文档关闭、HTA 窗口关掉、服务被 SCM 杀掉）
```

## 一次只改一个变量

记录格式建议：

| 时间 | 改了什么 | 观察到什么 | 结论 |
|---|---|---|---|
| 10:12 | 只换 x64 版本 | 仍闪退 | 不是位数问题 |
| 10:18 | 换成无害 hello | 能跑 | 问题在载荷内容，不在投递 |

「同时改编码、换端口、换宿主」会让你无法复现。

## 静态 vs 行为

| 现象 | 更像 |
|---|---|
| 文件落地前或落地即消失，无害程序却能保存 | 静态特征 / 扩展名 / 区段特征 |
| 能启动，跑到某 API 或出网时被杀 | 行为监控 |
| 只有 PowerShell 脚本被拦，同样逻辑的 EXE 能跑 | 脚本扫描（AMSI 等） |
| SYSTEM 会话出不了网，用户会话可以 | 代理 / WinHTTP vs WinINet，见 [出网通道](/topics/egress) |

无害对照（只打印、只回调、只写文件）是最便宜的探针。没有对照，就无法判断是投递失败还是内容被拦。

## 进程链

Office 宏弹出 `powershell.exe`、HTA 再拉起 `cmd.exe`，和「只在 `WINWORD.EXE` / `mshta.exe` 里执行」是完全不同的检测面。被拦时先看是不是**子进程**被策略杀掉，而不是先改 shellcode。
